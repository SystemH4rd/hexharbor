# Быстрый запуск HexHarbor

Сайт опубликован: https://systemh4rd.github.io/hexharbor/ . Репозиторий: https://github.com/SystemH4rd/hexharbor . Публикация через GitHub Actions прошла успешно; HTTPS включен. Проверены все три режима и навигация. Все результаты в интерфейсе синтетические.

## Посмотреть локально

Нужен Python 3. Откройте терминал в этой папке:

```sh
python3 -m http.server 8000 --directory docs
```

Откройте http://localhost:8000. Для каждого режима нажмите «Показать пример». Простое открытие index.html как file:// не подходит для модулей и JSON-фикстур.

## Обновить опубликованный сайт

Изменения в ветке main этого репозитория автоматически запускают проверки и публикацию. Для локальной копии:

```sh
git clone https://github.com/SystemH4rd/hexharbor.git
cd hexharbor
npm test
npm run check
```

После своих изменений сохраните их коммитом и отправьте в main. Результат смотрите во вкладке Actions.

## Вспомогательный скрипт создания репозитория

Текущий репозиторий уже создан. Скрипт ниже предназначен для первоначального создания и остановится при обнаружении существующего hexharbor.

Нужны Node.js 22+, Git, GitHub CLI (gh), curl и учётная запись SystemH4rd.

```sh
gh auth login --hostname github.com
bash scripts/publish.sh
```

Скрипт сначала проверит проект, затем создаст **новый публичный SystemH4rd/hexharbor**, отправит файлы, включит GitHub Pages через Actions, дождётся результата и выведет фактический HTTPS-адрес. Вход и публикация этим скриптом в текущей сессии не выполнялись. Скрипт проверен синтаксически; удалённый запуск требует вашей авторизации.

Если репозиторий hexharbor уже существует или в локальной папке настроен origin, скрипт остановится без изменения существующего репозитория. Если создание прошло, а последующий шаг завершился ошибкой, продолжайте из уже созданного репозитория через Settings → Pages → Source: GitHub Actions и Actions → Publish HexHarbor → Run workflow. Повторный запуск скрипта не перезапишет такой репозиторий.

Первый запуск Actions от push может начаться до включения Pages. После включения скрипт отдельно запускает workflow вручную.

## Содержимое

docs/ — только публикуемый сайт: HTML, CSS, JS, изображения, тестовые данные и JSON-схема.
.github/workflows/pages.yml — проверки и публикация.
scripts/check.mjs и tests/ — проверки.
ARCHITECTURE.md — связи компонентов.
ACCEPTANCE.md — результаты фактически проведённой проверки.

Фото остаётся в браузере. Экспорт содержит только демонстрационные записи. Реальных OSINT-запросов, API-ключей, персональных баз и распознавания лиц в этой версии нет.
